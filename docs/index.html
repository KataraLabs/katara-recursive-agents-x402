KATARA / DEMO GUIDE

One command. A tree of researchers. Cited results.

Five examples using Katara Cortex, paid per call through x402: test USDC on Avalanche Fuji while you try them, native USDC on Avalanche C-Chain for real. Offline fixtures are available without a wallet. Reports stay in your checkout.

Give a command to the master demo agent. Katara Cortex plans the specialist assignments; each specialist asks Katara Cortex to assign its researchers. Researchers collect public sources and return cited findings. Specialists combine their children’s work, and the master writes the final answer.

Start a demo

Use Node.js 22.14 or later. Run these commands from the repository root:

npm ci
npm run check
npm run demo -- list
npm run demo -- run all --offline

The offline run proves orchestration and report generation using labeled synthetic data. It makes no model calls, payments, or source requests.

For paid runs, create a wallet once; it starts on Katara's Test network, which pays in test USDC on Avalanche Fuji. If you already have a configured .env, keep it and skip wallet creation.

npm run wallet
npm run faucet
npm run demo -- doctor

npm run faucet claims 5 test USDC once a day and approves Permit2; it needs a little Fuji AVAX for gas and says where to get it when there is none. For Live, set KATARA_MODE=live in .env and fund the wallet with native USDC on Avalanche C-Chain, token 0xB97EF9Ef8734C71904D8002F8b6Bc66Dd9c48a6E. The client fixes the gateway, chain, token and settlement contract for each network; the payment reference lists them and where Katara publishes them. The private key stays in the ignored, mode-0600 .env. Paying for a call does not submit a buyer transaction; Katara submits the settlement.

npm run demo -- sources all
npm run demo -- run all --budget 7.00
npm run demo -- reconcile
npm run demo -- inspect

Live runs spend USDC and require an explicit --budget. Each completion call is a separate x402 payment of at least 0.05 USDC, so the 91 fixture calls of all five examples need at least 4.55 USDC, and live reviews and repairs add more. The budget is a maximum for the whole invocation, not a price estimate. Hold at least the budget in the wallet. Completion of every example within that amount is not guaranteed: quotes, repairs, and uncertain authorizations count against it. Running the command again starts a new budget. A new paid batch is refused while a previous authorization remains pending.

How recursion works

Public command
  Master agent: paid Katara Cortex plan
    Specialist agents: paid Katara Cortex plans
      Researcher agents: free source reads + paid Katara Cortex analysis
    Specialist agents: paid Katara Cortex synthesis of child findings
  Master agent: paid Katara Cortex review of cited source support
  Master agent: paid Katara Cortex synopsis of supported findings
  Master agent: paid Katara Cortex review of the final synopsis
HTML report + JSON evidence + Avalanche settlement reconciliation

These are logical agents in one TypeScript process, with distinct tasks, source permissions, parent IDs, and outputs. They share a wallet and inference client. The runtime recursively invokes children and awaits their results; Katara supplies the paid model completions. The scenario fixes the tree and source permissions, while Katara Cortex generates the task assignments. Katara Cortex tool calling and structured-output flags are not required: the runtime validates ordinary completion JSON.

The maximum tree has 16 agents across three levels. At most two model calls run concurrently by default; a parent releases its inference slot before waiting for children. Each response gets at most one schema repair, each agent at most eight inference calls, and each example a five-minute deadline. Retries remain subject to the shared spending cap.

Change an example

Each example folder contains scenario.json, its walkthrough, and source assignments. Change the scenario to adjust roles, tasks, and allowed sources. Use --command to change the public task without changing the tree:

npm run demo -- run repository --budget 1.50 --command "Explain Express request handling for a new contributor."
npm run demo -- plan all

Only public inputs belong in a demo command. The command and structured findings appear in the report. Keys, payment signatures, raw model transcripts, and complete source articles are excluded from public exports. Bounded source views and revision drafts remain in ignored local storage for source review.

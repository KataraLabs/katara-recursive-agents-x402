Extend the recursive-agent demos

Routine checks use offline fixtures. Live inference spends native USDC through x402 and requires the current user's authorized cap, a verified settlement contract and a funded wallet.

Follow a request

cli.ts: parse arguments and resolve configuration
examples.ts: load and validate a fixed scenario
runtime.ts: master plans specialists; specialists plan researchers
sources.ts + http.ts: collect permitted public sources
inference.ts + ledger.ts: reserve and sign x402 inference payments
review.ts: assess cited findings against source spans
synopsis.ts: write the master answer from supported findings
review.ts: check and replace unsupported master sections
chain.ts: reconcile finalized USDC charges
report.ts + evidence.ts: preserve evidence and render the answer

Katara Cortex supplies ordinary model completions. The TypeScript runtime creates the recursive tasks, constrains source access and waits for child results. No local service stack or model tool-calling interface is needed.

Change an existing example

  1. Edit its examples/<id>/scenario.json. Use unique IDs and explicitly assigned source IDs. Maintain at most four specialists, one to three researchers each, and sixteen total agents.
  2. For a new endpoint format, change src/sources.ts and test its window and missing-data behavior. Preserve HTTPS host checks and connection-time public-IP validation in src/http.ts.
  3. For a different final answer structure, update synopsisHeadings and scenario guidance in src/synopsis.ts. Keep source reviews and missing-evidence handling intact.
  4. Regenerate documentation and run the offline checks. Inspect the master synopsis and JSON evidence, not just the process exit code.

Add another example

Create examples/<new-id>/scenario.json, add its identity to ExampleId in src/types.ts, register it in src/examples.ts, and add its headings and guidance in src/synopsis.ts. Update scenario-specific walkthrough guidance in scripts/build-docs.ts, the README table and any labels that assume five examples. The runtime, fixtures and indexes enumerate the registry, but identity unions and scenario prose must also agree. Run npm run docs and exercise the new example plus all registered examples.

Use the JSON CLI

npm run --silent demo -- list --json
npm run --silent demo -- plan all --json
npm run --silent demo -- run all --offline --json
npm run --silent demo -- inspect <run-id> --json

All CLI commands accept --json. The process emits exactly one JSON envelope to stdout, with schemaVersion: 1 and ok. Success includes result; failure includes a stable error code and may include partial results. Exit status is zero for success and one for failure or partial execution. JSON mode suppresses human progress lines. Use npm run --silent to suppress npm's own banner, or node dist/cli.js after building.

doctor --json performs read-only checks. configurationVerified is separate from paidCapacityVerified, which stays false. sources --json retrieves public data without paying. run spends money unless --offline is supplied, even when its output is JSON. reconcile reads chain evidence and updates local accounting.

Data contracts

  • Scenario v1: tasks and source scopes.
  • Run report v1: progress, findings, source reviews and payments.
  • Synopsis revision v1: corrections tied to immutable input hashes.
  • CLI response v1: structured success and failure envelopes.

The schemas use JSON Schema draft-07 and are self-contained. TypeScript contracts and their JSDoc constraints generate them. npm run schemas writes them; npm run schemas:check refuses drift. Unknown object fields are rejected, optional fields are omitted rather than null, and USDC accounting uses decimal integer strings in six-decimal base units. Schema validation checks structure; runtime checks also enforce matching source IDs, line bounds, nonce uniqueness, budgets and finalized settlement.

JSDoc and generated files

The API reference is derived from exported declarations and public methods in src/ and scripts/. Document behavior, side effects, cancellation, monetary units and error boundaries. Use @param, @returns, @throws or @remarks where they explain the contract. Schema properties also support @minimum, @maximum, @minLength, @maxLength, @minItems, @maxItems, @pattern and @integer. Breaking wire changes require a deliberate schema-version decision.

Review and release

Run the documented workflow from a fresh checkout with no wallet or parent workspace. Review dependency updates before merging. Preserve MIT and source attribution. Keep raw local source snapshots and revision drafts private; exported findings still require review before sharing. The first public release uses one root commit, and publishing requires the current user's explicit authorization.
